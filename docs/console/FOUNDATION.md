# HermesOps Console Foundation

Status: **2P foundation extended through 2U objective lifecycle**

## Purpose

The HermesOps Console is the dedicated browser client for the HermesOps
Controller. Milestone 2P installed the deterministic static build, hardened
loopback HTTP service, navigation shell, and bounded probes. Milestone 2Q adds
the narrow same-origin browser session and Controller client boundary. Milestone
2R adds six explicit, query-free, read-only operational collection routes.
Milestone 2S adds a closed project lifecycle gateway and project page. The
current Console includes a dedicated Blueprint editor, validation preview,
immutable history, and canonical path comparison.

The Console remains unprivileged. It never opens SQLite, project workspaces,
the Hermes Agent endpoint, Docker sockets, or host paths.

## Deployment

| Component | Binding | Role |
| --- | --- | --- |
| Hermes Agent | `127.0.0.1:8642` | Upstream AI gateway |
| Controller API | `127.0.0.1:8765` | Authoritative control plane |
| Legacy Hermes WebUI | `127.0.0.1:8787` | Temporary direct Agent compatibility UI and current Controller trusted origin |
| HermesOps Console | `127.0.0.1:8788` | Dedicated HermesOps product UI and browser origin |

The new Console does not replace or modify the legacy WebUI. It has no gateway
credential or Agent network path.

## Browser-to-Controller transport

The browser calls only relative same-origin paths on port 8788. The Console
service accepts exactly the authentication/session and capability routes listed
in [Controller client](CONTROLLER_CLIENT.md), validates the browser origin, and
forwards them to the loopback Controller. It strips Controller CORS headers and
reapplies Console security headers.

The CSP now uses `connect-src 'self'` and `form-action 'self'`. WebSocket remains
disabled and is assigned to a later milestone.

## Dependency posture

The Console has no Node.js, npm, pnpm, yarn, CDN, third-party script, font,
image, or runtime dependency. The committed distribution is generated by
`scripts/hermesops-console-build.py` using Python 3.11 standard library only.

The build is deterministic:

```bash
python3 scripts/hermesops-console-build.py check   --source console/src   --expected console/dist
```

The exact source file set is closed. Symlinks, hard-linked source files,
unexpected files, invalid UTF-8, NUL bytes, empty files, and oversized files are
rejected before output is replaced.

## Routes

The product shell serves `/dashboard`, `/projects`, `/blueprints`, `/objectives`, `/executions`,
`/reviews`, `/events`, and `/administration`. The service endpoints remain
`GET|HEAD /health` and `GET|HEAD /version`. Controller gateway paths are
separately allowlisted and never use generic filesystem or URL routing.

## HTTP safety

The service binds only to loopback, serves exact route/asset/API allowlists,
rejects malformed Host/origin/framing/header/body inputs, bounds concurrency and
upstream responses, applies timeouts, never follows redirects, and emits
redacted problem documents.

## Service operations

```bash
systemctl --user status hermesops-console.service
curl --fail http://127.0.0.1:8788/health
python3 scripts/hermesops-console-probe.py   --base-url http://127.0.0.1:8788
```

## Current non-goals

The Console implements the bounded dashboard, project lifecycle, Blueprint
lifecycle, and objective lifecycle. It does not build or activate
images, bind secrets, delete revisions, expose objective task details or
unsupported objective commands, implement execution views, human review
actions, WebSocket events, browser persistence, service workers, or offline
command queues.


Milestone 2U replaces the objective placeholder with a bounded lifecycle page.
It reuses the secure Controller command foundation, adds no migration, and does
not expand into task/run detail or realtime reconciliation.
